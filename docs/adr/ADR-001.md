# ADR-001: Supervisor Daemon Port Allocation

**Status**: Accepted
**Date**: 2026-02-22
**Deciders**: NTM core team

## Context

The NTM supervisor dynamically assigns ports to managed daemons at startup. The `DefaultAgentMailURL` in the NTM config is hardcoded to `http://127.0.0.1:8765/mcp/`, which means the `am` (Agent Mail) daemon must receive port 8765 or any session that relies on the default URL will fail to connect. A secondary default of 8200 is assigned to `cm` (CASS Memory). At startup, the supervisor checks whether each default port is available; if a port is occupied, it falls back to a random available port.

## Decision

`am` is listed first in `DefaultSpecs()` and is assigned default port 8765. `cm` is assigned default port 8200. After the OS allocates the actual port, the supervisor re-assigns the `HealthURL` to reflect the dynamically allocated port rather than leaving it pointing at the default.

## Consequences

- Changing `DefaultAgentMailURL` in config requires a matching change to `am`'s `DefaultPort`; the two values are coupled and must be kept in sync.
- Port 8200 for `cm` may conflict with other services running on a developer machine (e.g., some HTTP proxies or monitoring agents), though this is rare.
- Fallback to a random port means the supervisor remains functional under port contention, but the random port will not match any hardcoded client URL, so callers must discover the actual port via the supervisor's registry rather than relying on the default.
