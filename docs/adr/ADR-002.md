# ADR-002: bd Removed from Supervisor (No Daemon Mode)

**Status**: Accepted
**Date**: 2026-02-22
**Deciders**: NTM core team

## Context

An earlier version of `DefaultSpecs()` included a `bd` daemon spec with `Args: ["daemon", "--start", "--foreground", ...]`. Investigation revealed that `bd` has no `daemon` subcommand — it is a synchronous CLI tool for beads issue management, not a long-running process. Attempting to start it via the supervisor caused exec failures immediately at launch.

## Decision

`bd` is removed from `DefaultSpecs()` entirely. The supervisor no longer attempts to manage it as a daemon. All `ntm beads daemon *` CLI subcommands (`start`, `stop`, `status`, `health`, `metrics`) are retained in the CLI for discoverability and user-facing clarity, but each returns an informative error message: "bd does not support daemon mode; use 'bd sync' to sync issue state manually."

## Consequences

- The `ntm beads daemon` command tree still exists and is documented, but it performs no action. This avoids silent command-not-found errors for users who attempt to use it.
- Users who expected `ntm beads daemon start` to manage background sync must switch to running `bd sync` manually or via a cron/launchd schedule.
- The supervisor startup sequence is simpler and no longer fails due to a missing `bd` subcommand.
