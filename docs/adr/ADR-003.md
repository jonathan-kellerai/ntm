# ADR-003: am serve-http Subcommand Selection

**Status**: Accepted
**Date**: 2026-02-22
**Deciders**: NTM core team

## Context

The `am` binary provides two serve modes:

- `serve-http` — HTTP/JSON API server on a configurable port, with a `/health/liveness` endpoint.
- `serve-stdio` — stdio-based MCP transport, used for direct process-to-process communication without a network socket.

NTM's supervisor starts daemons and monitors them via HTTP health checks. An earlier `DefaultSpecs()` used `Args: ["serve"]`, which is not a valid `am` subcommand; this caused the process to exit immediately, making the health check permanently fail.

## Decision

NTM's supervisor starts `am` with `serve-http`. The health URL is `http://127.0.0.1:<port>/health/liveness`, where `<port>` is the dynamically allocated port described in ADR-001.

## Consequences

- `am serve-stdio` is not managed by the NTM supervisor. Teams that need stdio transport must start it independently, outside of NTM's process management.
- Using `serve-http` means `am` binds a network socket. On machines with strict firewall rules or loopback restrictions, this may require explicit allow-listing of the loopback interface.
- The HTTP mode enables straightforward health monitoring and future REST API access to Agent Mail from other tools.
